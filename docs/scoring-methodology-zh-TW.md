# FOMC 鷹派/鴿派分數公式修訂說明

本文件記錄既有 FOMC v4 計分規則與修訂理由，適用於本 repository 的歷史分數。歷史 toneAdj 由人工判讀；自動更新的新會議改由 Anthropic 依本文件的 -2 至 +2 量尺產生 toneAdj，再沿用相同加權公式。完整分數資料見 `../data/fomc_hawkish_scores.csv`；舊版完整資料未包含在這個獨立 repository。

## 1. 原公式的問題

原本的計分邏輯：

```
initialScore = rateBase(action, bp) + toneAdj + qeAdj + qtAdj + bondAdj
（再經 applyRateConstraints 依 action/bp 強制夾到某個上下限）
```

主要問題：

1. **`applyRateConstraints` 事後鉗制，讓 tone/QE/QT/bond 幾乎白加。** 只要是升息會議分數就被強制夾到高分區、降息會議夾到低分區，其他因子只能在被夾死的範圍內做極小幅微調，公式看起來是多因子加權，實際上幾乎只看這次有沒有升降息。
2. **`bondAdj`（會議前公債殖利率斜率）跟利率決策本身高度相關**，市場通常已提前 price in 該次會議結果，拿它加進最終分數有雙重計算風險。
3. **`toneMap`／`qeMap`／`qtMap` 全部是人工逐場填的判斷值**，20 年、170 場會議由同一人一次性標註，沒有交叉驗證，标准可能隨時間漂移，但這點目前選擇維持人工判斷（見下方「維持不變的部分」），只調整了聚合方式。
4. **精度跟輸入品質不成比例**：人工給的整數判斷（-2~2）卻用 `Math.round(score*4)/4` 算到小數點後兩位，製造假精確。
5. 原文件修訂時曾擔心表格包含尚未確認的 `2026-09-16` 會議。這是當時的資料狀態疑慮；目前該日期已由官方 FOMC 聲明稿確認。

## 2. 新公式

```
score = clamp( 5 + w_rate × rateSignal + w_tone × toneSignal + w_asset × assetSignal + dissentAdj, 0, 10 )

w_rate = 3, w_tone = 1, w_asset = 2   ← 已依討論調高 rateSignal 權重（原本 w_rate=2）
```

範圍檢查：理論最大 = 5+3+1+2 = 11，理論最小 = 5-3-1-2 = -1，**超出 0~10 量表**，因此最終分數需要一個邊界 clamp。**這跟問題1原本批評的「事後鉗制」在形式上類似，差別在於：這裡只在少數觸及邊界的極端案例才會被夾到（實測170場中只有2場：2008-12-16、2020-03-15），且不像原公式的 `applyRateConstraints` 會用 action/bp 覆寫掉其他因子的作用——多數會議的分數仍完整反映三個signal的加權和，沒有被截斷。**

`bondAdj` 直接拿掉，不再放進最終分數（解決問題2）。

### 2.4 dissentAdj（明確利率異議，小幅修正）

只計入聲明稿中**明確說明偏好另一個聯邦基金利率／目標區間**的異議。對聲明措辭、資產購買、準備金或前瞻指引的異議不計分。方向以多數決策為基準：多數維持時，偏好升息為鷹派、偏好降息為鴿派；多數升息時，偏好維持為鴿派；多數降息時，偏好維持為鷹派。

```
netDissent = dissentHawkishCount - dissentDovishCount
dissentAdj =  0.1  （netDissent =  1 或  2）
             0.2  （netDissent ≥  3）
            -0.1  （netDissent = -1 或 -2）
            -0.2  （netDissent ≤ -3）
             0    （沒有可辨識的利率異議，或鷹、鴿人數相抵）
```

CSV 新增 `dissentHawkishCount`、`dissentDovishCount`、`dissentAdj`、`dissentReason` 四欄。這是直接加在 0–10 分數上的微幅調整，不另設權重，避免使少數委員的異議蓋過多數決策。

### 2.1 rateSignal（利率決策，客觀計算，不需人工判斷）

```js
const bpSigned = action === "升息" ? bp : action === "降息" ? -bp : 0;
const rateSignal = clamp(bpSigned / 75, -1, 1);
```
**（已依討論修改）** 原本以100bp當±1基準，改為以 **75bp 當滿分基準** ——只要單次升/降息達到75bp（如2022年連續四次75bp升息）就直接打滿 ±1，不用等到100bp才封頂。連帶把 `w_rate` 從2調高到3，讓利率決策本身在最終分數中的份量變重。

換算對照：25bp→±0.33、50bp→±0.67、75bp(含以上)→±1.0（封頂）。

### 2.2 toneSignal（文字語氣，沿用原有人工判斷）

```js
const toneSignal = clamp(toneAdj / 2, -1, 1);
```
沿用原本 `toneMap`（人工填的 -2~2 整數），因為改用可重現的關鍵字演算法（`keywordToneScore`）需要用全樣本校準一個縮放常數，新增會議會牽動歷史分數的疑慮（已討論並否決），所以保留人工判斷，只是把它正規化到 -1~1。

### 2.3 assetSignal（QE/QT 及其他資產負債表工具，轉折式判斷）

**核心原則：分數看的是「這次動作相對於前一次政策軌跡的轉折方向」，不是動作本身的絕對狀態。** 例如「暫停QT」是從「持續緊縮」轉向「完全停止」，是鴿派意外，應給負值；「持續QT（無新增動作）」則是符合預期、沒有新訊號，給0。

| 標籤 | assetSignal | 說明 |
|---|---|---|
| 開始QT | +1.0 | 從中性/寬鬆轉為緊縮，最強鷹派意外 |
| 持續QT（無新增動作） | 0 | 符合預期，無新訊號 |
| 減少QT | -0.3 | 緊縮放緩，鴿派意外，但方向仍是緊縮 |
| 暫停QT | -0.5 | 緊縮完全停止，更大的鴿派意外 |
| 開始QE / 擴大QE | -1.0 | 從中性/緊縮轉為寬鬆，最強鴿派意外 |
| 持續QE（無新增動作） | 0 | 符合預期 |
| 減少QE（taper） | +0.3 | 寬鬆放緩，鷹派意外，但方向仍是寬鬆 |
| 暫停QE | +0.5 | 寬鬆完全停止，更大的鷹派意外 |
| 準備金管理型短債購買（RMP等，官方定位「非QE」的短天期流動性工具） | -0.2 | 中性狀態下小幅偏向寬鬆，幅度遠小於正式QE，因為只買短天期、不影響存續期風險，且官方明確不定位為政策轉向 |
| 無明確QE/QT動作 | 0 | fallback |

**判斷新工具時的三個問題**（用於表格沒列出的工具）：
1. 買/賣的資產天期長不長？（短天期→靠近0，長天期→靠近±1）
2. 是開放式政策還是一次性/技術性操作？（開放式→放大幅度，技術性→縮小幅度）
3. Fed 官方怎麼定位這個工具？（政策轉向工具→放大，純維穩→趨近0）

**⚠️ 修訂過程中的一個實際錯誤（留作紀錄）**：初版曾把「暫停QT」誤標成正值／鷹派方向，邏輯是「完全暫停比放慢更接近中性」，但這跟原始 `qtMap` 資料本身的符號慣例矛盾——原始資料把「減少QT」「暫停QT」都給負值，因為兩者都是「相對於預期持續緊縮的鴿派意外」。修正後兩者都改為負值（減少QT -0.3、暫停QT -0.5）；以目前權重重算，2025-10-29（降息+暫停QT同時發生）為 2.50。**教訓：任何新的 fuzzy signal 值都要先對照原始資料的既有符號慣例，不能憑空重新定義方向。**

## 3. 維持不變的部分（討論中明確否決的方案）

- **不採用純關鍵字演算法（`keywordToneScore`）取代人工 `toneMap`**：雖然可重現性更好，但需要用歷史樣本校準一個縮放常數（如 p95），新會議加入理論上會微幅牽動這個常數，進而讓歷史分數跟著變動，使用者認為這個「新資料改動舊分數」的特性不可接受，故保留人工 `toneMap`。
- **不採用 Fed 資產負債表實際數據（H.4.1 / SOMA holdings）取代聲明稿文字判讀**：雖然能徹底解決「工具還在運作但聲明稿沒提到」的問題（例如 RMP 持續進行但某幾場會議沒重提），但使用者認為官方資產負債表數據更新有落後，故放棄，改為接受「聲明稿沒提到=能查到的最新狀態延續，若未提及新變化則維持前值」的限制，未建立自動化的狀態延續機制（避免複雜化），仍以人工逐場判讀轉折類型為主。
- **不採用公式化的 `durationWeight × openEndedWeight × directionSign` 計算 assetSignal**：使用者要求「不要用公式」，故 assetSignal 改回直接查表（人工分級表），只是分級邏輯本身改採「轉折式」判斷（見 2.3）。

## 4. 已知限制（尚未解決，留待未來考慮）

- `toneMap` 仍是純人工判斷，170 場會議由同一人一次性標註，沒有跨標註者一致性檢查。
- 若某個資產負債表工具（如 RMP）持續運作但某場會議聲明稿未重提，目前做法是該場會議的 `assetSignal` 直接算 0（無新增動作），不會自動延續前一場的寬鬆/緊縮訊號——這是文字判讀法本身的限制，經討論後選擇接受、不额外處理。
+ 原始修訂文件曾提醒確認 `2026-09-16` 是否為預測值；此日期目前已由 Federal Reserve 官方聲明稿確認，GitHub 初始化資料亦保存該官方來源。

## 5. 全量執行結果摘要（基本權重：w_rate=3、75bp封頂）

- 共 170 場會議（2006-01-31 ~ 2026-09-16）
- 分數分布：最小 0.00、最大 10.00、平均 4.94；36 場的淨利率異議使 `dissentAdj` 非 0。
- 最低分（0.00，觸底clamp）：2008-12-16、2020-03-15，皆為「急降息100bp + 語氣轉鴿 + 開始QE」同時發生，clamp前原始值為-0.5
- 最高分（10.00，剛好壓線）：2022-05-04，「升息50bp + 語氣最鷹(toneAdj=2) + 開始QT」同時發生
- 2022年四場75bp升息（06/15、07/27、09/21、11/02）分數皆為9.00，rateSignal已封頂至+1.0
+ 含異議調整的最新版逐場資料見本 repository 的 `../data/fomc_hawkish_scores.csv`。

## 6. 已知但尚未處理的疑慮（2025-09-18討論中提出）

檢視全量結果時發現：**2009-2012年（ZIRP+QE持續期）跟2020下半年-2021年（零利率+每月1200億QE）分數都停留在4.5左右，接近中性**，因為 `assetSignal` 只獎勵/懲罰「這次會議相對上次的新動作」，政策維持在極端寬鬆但沒有新公告的月份一律算0。這代表目前的分數衡量的是「**這次會議相對市場預期的意外程度**」，而不是「**當下政策絕對有多鬆/多緊**」。這兩種設計哪個才是這份分數表真正該呈現的內容，尚待使用者決定，目前先不修改。
